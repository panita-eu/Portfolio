Case Study — TXN—01

BMS Transaction
Redesign

Three of BMS's highest-traffic flows — Quotation, Purchase Request, and Invoice — rebuilt from the same brief: simplify the visual design, tighten the UX, shorten the path to done.

RoleUX/UI Design Team Lead
Scope3 modules · shared flow pattern
ConstraintLive across multiple client deployments
Year2025

Brief

The MD's ask arrived at business-level: improve the visual design, tighten the UX, and shorten the flow. No formal spec, no user research attached — translating that into concrete design decisions was the actual work.

Approach

Audited each flow step by step to separate genuine business logic from steps that existed by habit. Rebuilt the visual hierarchy so critical fields surface first, and replaced dead-end placeholders — sections that looked finished but didn't function — with working components.

Constraints

BMS is a TMES product, not a one-off build — this base design ships to every client, who then re-skin it to their own CI. Any change had to hold up as the foundation every deployment builds from, ruling out a full rebuild in favor of a targeted redesign.

Outcome

Across all three modules: the SKU list went from an empty placeholder to a searchable, paginated table; entries could finally be saved as drafts mid-flow; and financial fields were grouped so only what's relevant shows by default. Detail below.

Design shown is TMES's default CI. Client deployments re-skin colors, logo, and branding to their own identity, with further customization available on request.

01 / 03

Quotation

The clearest before/after: the old form's SKU List was a bare pagination control with no table, no search, and no way to add a line item on screen. The new version makes it the functional center of the form.

  • SKU List: placeholder → search, Import Data, editable rows, insert-below, real pagination (55 pages / 28,978 records)
  • Form split into labeled sections (Branch, Customer Details, SKU List) instead of one continuous column
  • Status shown as a stepper (Draft → Pending → Processing → Complete) instead of a single toggle
  • Summary regrouped — Subtotal → Discount → After Discount → Grand Total — with optional fields tucked behind "+ Add More Fields"
  • Added Save Draft and Preview; old form only had Cancel / Create New
02 / 03

Purchase Request

The old form carried a full shipping-address block regardless of relevance, and its Payment Method field sat there reading "No available options" — a broken state left visible to the user. The new version drops what doesn't apply and adds what procurement actually needs.

  • Split into Branch Information and Vendor Details instead of one Address block
  • Added Requested Date and Due Date — fields procurement needed that the old form didn't ask for
  • Added an Attachment upload (drag-and-drop) for supporting documents; old form had none
  • Removed the dead "No available options" Payment Method field
03 / 03

Invoice

The old "Bill Issue/Invoice" form had no way to trace a line item back to the sale order it came from — Refer Sale Order and Refer Delivery No. both sat empty with "No available options." The new form makes that link explicit, and separates what's owed from what's withheld.

  • Added explicit Document Type selector and an "Add Sale Order" action with SO Ref. per line
  • Grand Total called out in its own highlighted block instead of blending into the field list
  • Withholding Tax Amount and Net Amount to Pay split apart — old form only surfaced one lump Grand Total
  • Removed the two "No available options" reference fields that had no working source to link to
